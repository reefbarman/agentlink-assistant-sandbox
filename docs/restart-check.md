# Restart check

1. Summarize the change in a concise subject line.
2. Start the subject with an imperative verb.
3. Explain why the change is needed in the body.
4. Describe the outcome rather than every implementation detail.
5. Keep each commit message focused on one logical change.
6. Separate the subject from the body with a blank line.
7. Wrap body lines for comfortable reading in terminals.
8. Reference related issues when they provide useful context.
9. Call out breaking changes and required migration steps.
10. Record important tradeoffs behind nonobvious decisions.
11. Mention relevant tests and their results.
12. Use consistent terminology from the project.
13. Avoid vague subjects such as "fix stuff".
14. Exclude secrets and sensitive information from messages.
15. Proofread the message before creating the commit.

16. Edited by the owner in the editor takeover check.
